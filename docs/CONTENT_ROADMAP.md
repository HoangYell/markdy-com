# Content and SEO Roadmap

This roadmap identifies high-value pages that can help developers discover Markdy through the vocabulary they already search for while establishing Markdy as the AI-first animation and architecture DSL.

## Core positioning pages

1. **Mermaid Alternative for Animated Diagrams**
   - Search intent: "Mermaid alternative", "Mermaid animated diagrams", "Mermaid for animation".
   - Angle: keep Mermaid for static diagrams; use Markdy when timing, camera, and motion matter.

2. **Animated Architecture Diagrams as Code**
   - Search intent: "architecture diagrams as code", "infrastructure diagrams", "system architecture visualization".
   - Angle: version-controlled architecture flows with request/response/emit edges.

3. **AI-Generated Diagrams with an LLM-Friendly DSL**
   - Search intent: "AI generated diagrams", "LLM diagram generation", "AI coding agent diagrams".
   - Angle: MarkdyScript is easier for agents to generate and repair than imperative JavaScript.

4. **Markdown Animation for Developer Documentation**
   - Search intent: "Markdown animation", "docs as code animation", "animated developer documentation".
   - Angle: embed small motion scenes in docs without video tooling.

## Comparison pages

- Markdy vs Mermaid
- Markdy vs PlantUML

Each page should be honest: explain when the other tool is better, then show the Markdy use case where animation and AI generation matter.

## Content quality rules

- Solve a concrete developer problem on every page.
- Show runnable MarkdyScript, not abstract descriptions.
- Link to relevant examples under `examples/showcase/`.
- Use comparison pages to clarify fit, not attack alternatives.
- Keep pages useful for humans and parseable for AI agents.
